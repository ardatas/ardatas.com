CHECK24 MCP App
One ChatGPT-facing Model Context Protocol endpoint for four mocked product services.
Local application screenshot, 13 October 2026. The demo catalog exposes 11 tools and withholds one invalid tool. All product data is mocked.
WHAT I BUILT
For the CHECK24 GenDev scholarship task, I built a TypeScript proxy for hotel, flight, package-holiday, and insurance tools. Stable namespaced tool names map to the original service tools behind one public catalog.
VALIDATION AT THE BOUNDARY
AJV validates tool schemas and incoming arguments. If a tool declares structured output, the proxy validates that too. Invalid tools are withheld with a rule, severity, and a suggested fix exposed in JSON and the dashboard.
A CONCRETE FAILURE CASE
The insurance mock intentionally omits an input schema for one tool. The proxy withholds it and reports <font face="Mono">inputSchema_missing</font>. Reviewers can inspect the same validation boundary through service-specific QA routes.
<b>Stack:</b> TypeScript, Node.js, Express, MCP SDK, AJV, Vitest, Docker Compose.
LOOK CLOSER
A usable tool catalog needs explicit validation failures and traceable routing, as well as aggregation.

Julia Set Explorer
A team-built C renderer, with an interactive WebAssembly version on my portfolio.

Left: color output captured from the browser explorer. Right: the team report's native C benchmark, using grayscale output; these are separate rendering contexts.
MY CONTRIBUTION
I profiled the SIMD implementation and investigated the active-mask bottleneck. I fixed escaped-lane reactivation, replaced masked addition with subtraction, added monotonic timing and BMP dimension checks, and designed correctness and performance experiments.
HOW THE RENDERER WORKS
SIMD processes four pixels in parallel. Each lane iterates the Julia recurrence until it escapes or reaches the iteration limit. Active masks keep escaped lanes inactive. A scalar fallback handles widths that do not fill a complete SIMD group.
BENCHMARK AND CORRECTNESS EVIDENCE
Reported mean over 100 runs: <b>13.18 ms scalar</b> and <b>4.30 ms SIMD</b> at 800 x 600 pixels and 100 iterations. Hardware: AMD Ryzen 9 5950X; compiler: GCC 14.2.0, C17, -O3, -msse4.2. The team report records byte-identical SHA-256 comparisons across more than 30 scenarios.
The core SIMD implementation was written by a teammate. My focus was profiling, correctness fixes, experiments, and performance visualization. Timings are reported project results.
LOOK CLOSER
Performance work needs a reference implementation and tests for lane divergence and edge cases.
